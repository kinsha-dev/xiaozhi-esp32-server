# Mac menu-bar voice app Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A macOS menu-bar app that replaces the ESP32 board: wake phrase "Hi bibi" on the Mac mic, conversation with the unchanged xiaozhi server, replies through the Mac speakers.

**Architecture:** A websocket client speaking the board's protocol to `ws://localhost:8000/xiaozhi/v1/` (hello, listen, Opus up/down). A local wake detector (webrtcvad segmentation + Whisper `tiny.en`, fuzzy phrase match) gates all mic audio; nothing leaves the Mac before the wake phrase. Pending `vibi` outbox rows trigger a session by sending the server a `detect` of "hi vibi" (the server's existing `vibi_outbox.wake_text` then reads them out).

**Tech Stack:** Python 3.12 (server venv), `websockets` 14, `opuslib_next`, `webrtcvad`, `openai-whisper`, new: `sounddevice`, `rumps`. pytest (asyncio_mode=auto).

**Spec:** `docs/superpowers/specs/2026-11-01-mac-app-design.md`

## Global Constraints
- Code lives in `main/xiaozhi-server/mac_app/` (package), tests in `main/xiaozhi-server/tests/test_mac_app_*.py`. (Changed from spec's `voice-note-box/mac-app/`: this repo is the branch being worked on; builder's note: the spec location was my guess.)
- Wake phrase default `"hi bibi"`, configurable via `MAC_APP_WAKE` env; accept "hi/hey" + "bibi/vibi/bee bee/vivi".
- Audio up: Opus, 16000 Hz, mono, 60 ms frames. Audio down: Opus at the sample_rate/frame_duration in the server hello (24000, 60).
- Mic audio is dropped (never sent) while idle or while the app is speaking.
- Server URL from `MAC_APP_SERVER` (default `ws://127.0.0.1:8000/xiaozhi/v1/`); headers `device-id: mac-app`, `client-id: mac-app`. Auth is disabled in server config.
- Outbox dir from `VOICE_BOX_DATA` (default `<xiaozhi-server>/data`), file `outbox.jsonl`, rows with `"status": "pending"`.
- Must not change any server file; board and Mac app can connect concurrently.

## Review Focus
- Mic denied / no input device: menu shows an error state, app does not crash or spin.
- Server down or restarting: reconnect with backoff on the next wake; wake detector keeps running.
- Server speech echoed into the mic must not re-trigger the wake phrase (mute during playback + 0.5 s tail).
- Whisper hallucinations on silence/noise ("Thank you.") must not match the wake phrase.
- Muted state: no upload, no wake detection, outbox polling still notifies but does not open a session.
- Long idle (server closes after 120 s): session ends cleanly and returns to idle.

### Task 2: Wake phrase matching and detector

**Interfaces:** Produces `matches_wake(text: str, phrase: str = "hi bibi") -> bool`; class `WakeDetector(transcribe: Callable[[np.ndarray], str], phrase: str)` with `feed(frame: bytes) -> bool` (16 kHz int16 mono, 30 ms frames of webrtcvad aggressiveness 2; returns True once when a finished speech segment, ≤3 s, transcribes to a match); `whisper_transcriber(model: str = "tiny.en") -> Callable[[np.ndarray], str]`.
- [ ] Tests (`matches_wake`): `"Hi Bibi."`, `"hey vibi"`, `"Hi, bee bee!"`, `"hi vivi"` match; `"Thank you."`, `""`, `"hi there"`, `"bibi"` alone (no greeting) do not; match is allowed inside a longer utterance only if it starts the text (`"hi bibi what time is it"` matches, `"say hi bibi"` does not).
- [ ] Tests (`WakeDetector`, fake transcribe): speech-like frames then silence calls `transcribe` once and returns True on match; pure silence never calls `transcribe`; segment longer than 3 s is truncated to its last 3 s; after a match, `feed` returns False until the next segment.
- [ ] Implement; whisper loaded lazily on first transcription, `fp16=False`, `no_speech_threshold` default. Commit.
